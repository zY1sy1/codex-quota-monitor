# 自适应主题设置中心设计

## 1. 背景

当前设置窗口是一个宽度 420 DIP、按内容自动增高的单列 WPF 表单。显示模式、主题和完整窗口布局分别放在三个 `GroupBox` 中，窗口行为、刷新和中转站入口继续向下堆叠。界面功能完整，但存在以下问题：

- 所有设置平铺在同一列，缺少稳定的信息架构，后续增加设置只能继续拉长窗口；
- 原生 `GroupBox`、单选按钮和普通按钮的视觉层级较弱，与额度窗口的深灰、青绿色设计语言不一致；
- 完整窗口布局在非完整模式下仍可操作，界面没有表达设置之间的依赖；
- 底部状态文本按内容增高，成功或错误消息可能改变窗口高度；
- 设置窗口固定为浅色，切换额度窗口主题时缺少连续反馈；
- 已批准的“中转站独立查询间隔”设计要求从本页移除全局查询间隔，因此当前页面结构即将再次变化。

本设计基于当前设置窗口在 100% 和 150% 缩放下的实际捕获结果，并沿用额度窗口已有的浅色、深色和青绿色主题资源。

## 2. 目标

- 把设置窗口改为可扩展的设置中心，使用左侧导航和右侧内容区；
- 设置中心随当前浅色或深色主题即时切换；
- 重新组织现有功能，不改变用户已经熟悉的即时生效语义；
- 明确完整窗口布局只适用于完整窗口模式；
- 让成功、错误和恢复状态在固定区域稳定展示；
- 保持键盘操作、自动化名称、焦点可见性和 150% 缩放下的可读性；
- 为后续页面保留清晰边界，但本次不展示未实现入口。

## 3. 非目标

- 不新增诊断、关于、日志查看、实时预览或其他业务功能；
- 不增加新的持久化设置字段或升级设置 schema；
- 不重新设计中转站管理器、CC Switch 导入窗口或额度窗口；
- 不改变模式、主题、布局、置顶、开机启动和刷新动作的运行时含义；
- 不把尚未实现的页面显示为禁用占位项；
- 不在本设计中重复定义中转站独立调度逻辑。

## 4. 选定方向

用户选择“完整设置中心”结构和“跟随主题”视觉方案。

第一版只显示三个可用页面：

1. `外观`：显示模式、主题、完整窗口布局；
2. `行为`：始终置顶、开机启动、立即刷新；
3. `中转站`：中转站说明和打开中转站管理器的命令。

每次打开设置窗口默认进入“外观”。当前页面属于视图临时状态，不写入设置文件。

## 5. 窗口与布局

- 初始尺寸为 720 x 520 DIP；最小尺寸为 640 x 460 DIP；窗口继续允许调整大小；
- 移除 `SizeToContent="Height"`，避免状态消息和页面内容改变外框尺寸；
- 保留系统标题栏、应用图标、居中启动、布局取整和设备像素对齐；
- 根布局使用两列：156 DIP 导航栏和可伸缩内容区；
- 内容区由页面标题、可滚动设置内容和固定高度状态栏组成；
- 内容区使用 24 DIP 外边距，设置行以 8 DIP 基线组织；
- 窗口缩小到最小尺寸时，只允许内容区纵向滚动，导航栏和状态栏保持可见；
- 不使用嵌套卡片。设置页面使用标题、说明、设置行和分隔线形成层级。

## 6. 视觉系统

设置中心复用现有 `Theme.ps1` 的核心语义色：主表面、次级表面、主文字、次级文字、强调色、选择面、分隔线、警告和错误。设置窗口使用不透明表面，避免普通桌面窗口出现不必要的透明合成。

### 6.1 浅色

- 内容表面接近白色；导航栏使用冷灰白次级表面；
- 选中导航项使用青绿色左边线和浅青选择面；
- 主文字使用深中性色，说明文字使用现有次级文字色；
- 分段选择的选中项使用青绿色实底或强调边框。

### 6.2 深色

- 内容表面沿用额度窗口的深灰蓝；导航栏使用更深的中性表面；
- 选中导航项使用亮青强调色和较深的青灰选择面；
- 主文字、次级文字、分隔线和错误色沿用现有深色 palette；
- 不使用渐变、装饰光斑或额外阴影层。

### 6.3 字体与尺寸

- 使用系统 `Segoe UI` 字体和默认字距；
- 页面标题 21 DIP、半粗；设置标题 13 DIP、半粗；说明 11 至 12 DIP；
- 导航项和交互控件最小高度为 36 DIP，主要命令按钮最小高度为 36 DIP；
- 圆角不超过 6 DIP；焦点轮廓使用主题强调色并与选择状态区分。

## 7. 组件与页面

### 7.1 设置中心外壳

外壳负责窗口主题资源、导航、页面可见性、固定状态栏和默认页面。导航切换只改变视图状态，不调用运行时回调。

### 7.2 外观页

- `显示模式` 使用三个等宽分段单选项：完整窗口、迷你条、额度球；
- `主题` 使用浅色透明和深色透明两个主题选项，并用实际浅色、深色色块强化识别；
- `完整窗口布局` 使用总览折叠和标签切换两个分段选项；
- 当模式不是 `Full` 时，完整窗口布局保留已保存值但禁用，说明文字固定显示“仅完整窗口模式可用”；
- 切换主题成功后，设置中心自身立即应用新的主题资源。

### 7.3 行为页

- `始终置顶` 和 `开机启动` 使用保留 `CheckBox` 语义的开关样式；
- 每个开关行包含标题和一行结果导向的说明；
- `立即刷新额度` 是独立命令按钮，说明其会请求官方和已启用中转站刷新；
- 页面不增加保存或取消按钮，所有更改继续即时生效。

### 7.4 中转站页

- 说明官方额度与中转站额度是独立数据链路；
- 提供一个明确的 `打开中转站管理器` 命令按钮；
- 不在设置中心复制 provider 列表、凭据、测试或查询间隔编辑器；
- 全局查询间隔控件不再出现，每个中转站的间隔由中转站管理器负责。

### 7.5 状态栏

- 状态栏位于内容区底部并保持固定高度；
- 空闲状态显示“更改即时保存”；配置变更成功后显示“设置已同步”；命令和错误显示各自的简短结果；
- 状态变化不调整窗口大小、不遮挡控件；
- 状态文本使用礼貌级辅助功能实时通知，避免普通导航变化产生重复朗读。

## 8. 交互与数据流

会修改持久化配置的动作采用统一数据流：

```text
用户操作
  -> SettingsView 回调
  -> SettingsController 调用现有运行时 action
  -> Controller 重新读取权威设置快照
  -> SettingsView 更新选择、禁用状态和主题资源
  -> 固定状态栏显示结果
```

具体规则：

- 每个用户操作只触发一次运行时回调；`SetSnapshot` 更新控件时不得反向触发回调；
- 模式、主题、布局、置顶和开机启动成功后都重新渲染权威快照；
- 主题重渲染同时更新设置中心的浅色或深色资源；
- 上述配置变更成功后统一显示“设置已同步”；
- 刷新成功后显示“已请求刷新”，不伪造刷新完成状态；
- 打开中转站管理器不改变当前设置页面；管理器关闭后设置中心仍可继续使用；
- 普通关闭、Alt+F4 和窗口关闭按钮继续隐藏设置窗口以便复用；释放控制器时才真正注销事件并关闭窗口。

## 9. 错误与恢复

- 运行时 action 抛出异常时，控制器先重新读取并渲染权威快照，再显示脱敏错误；
- 失败的开关、分段选择或主题切换不得停留在未保存的视觉状态；
- 错误只显示在固定状态栏，不新增模态错误框；
- 中转站管理器无法打开时，用户停留在中转站页并看到明确错误；
- 设置中心不吞掉既有日志记录，也不显示凭据、Token 或原始响应。

## 10. 可访问性

- 导航项、分段单选项和开关使用原生 WPF 可选择控件语义，不用普通 `Border` 模拟交互；
- 所有交互控件设置稳定的 `AutomationProperties.Name`；
- Tab 顺序依次经过导航和当前页面控件；状态栏不接收焦点，隐藏页面不进入焦点链；
- 分段单选项支持方向键，开关支持空格，命令按钮支持 Enter 或空格；
- 禁用的完整窗口布局仍保留可见说明，不能只用颜色表达原因；
- 浅色和深色的文字、边框、焦点和错误状态都需要做对比度检查；
- 截图只能验证可见风险，不能替代键盘和自动化树测试，也不宣称完整 WCAG 合规。

## 11. 与中转站独立间隔计划的关系

`docs/superpowers/specs/2026-08-30-provider-specific-relay-query-interval-design.md` 和对应实施计划已经定义：

- 删除设置窗口中的全局自动查询间隔；
- 让每个 provider 的 `IntervalMinutes` 成为唯一运行时调度来源；
- 保留设置 schema 3 中旧字段作为兼容数据，但不再接入 UI 或运行时。

该计划会修改与本设计相同的 `Settings.xaml`、`SettingsView.ps1` 和 `SettingsController.ps1`。实施时必须先完成中转站独立间隔计划，再基于移除全局间隔后的控件和回调合同构建设置中心，避免重复删除、冲突或短暂隐藏仍然生效的全局配置。

## 12. 测试策略

### 12.1 控制器单元测试

- 成功操作调用运行时一次，并用权威快照重渲染；
- 失败操作恢复快照并显示对应错误；
- 主题切换成功后快照主题与视图主题一致；
- 刷新只报告已请求，不报告已完成；
- dispose 清除所有回调且保持幂等。

### 12.2 WPF 组合测试

- 加载全部导航、页面、设置控件和状态栏；
- 固定中文文本、Tag、GroupName 和自动化名称；
- 导航只显示一个页面，默认页面为外观；
- 非完整模式禁用布局选择，恢复完整模式后重新启用；
- `SetSnapshot` 不触发 action 回调；
- 浅色和深色资源正确应用到外壳、导航、文字、分隔线、控件和状态栏；
- 普通关闭隐藏窗口，dispose 真正释放窗口。

### 12.3 视觉验证

视觉矩阵增加外观、行为和中转站三个页面，覆盖：

- 浅色与深色；
- 100% 与 150% 缩放；
- 完整模式与非完整模式下的布局启用状态；
- 普通、成功和错误状态栏。

检查窗口边界、文字裁切、滚动、焦点、对齐、圆角、分隔线和状态栏稳定性。最终至少检查 12 张基础页面截图，并对关键禁用和错误状态补充聚焦截图。

### 12.4 回归

- 运行完整 Unit 和 Integration Pester 套件；
- 运行 `git diff --check`；
- 确认设置 schema 和旧兼容字段测试继续通过；
- 确认部署目录没有被直接编辑。

## 13. 验收标准

1. 设置窗口显示外观、行为和中转站三个可用页面，没有未实现入口；
2. 浅色和深色选择会即时更新设置中心自身，重开窗口保持已保存主题；
3. 所有现有设置和命令继续即时生效，失败时界面恢复到权威状态；
4. 非完整模式不能修改完整窗口布局，但已保存布局值不丢失；
5. 成功和错误消息不会改变窗口尺寸或遮挡内容；
6. 键盘、焦点、自动化名称和 150% 缩放验证通过；
7. 设置窗口不再显示全局中转站查询间隔；
8. Unit、Integration 和视觉验证全部通过。
