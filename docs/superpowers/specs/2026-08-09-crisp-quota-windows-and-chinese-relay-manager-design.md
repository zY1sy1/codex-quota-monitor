# 配额悬浮窗清晰边缘与中转站中文界面设计

## 1. 背景与目标

当前完整悬浮窗、迷你条和额度球会在窗口初始化时启用 Windows DWM 背景模糊。由于这些窗口同时使用透明背景和半透明圆角容器，DWM 模糊会越过内容轮廓形成发灰、发糊的边缘。额度球还保留了旧的轨道与进度弧组合；历史上的同心修复曾提交，但随后被回滚，导致当前显示仍可能出现外圈与进度弧不一致。中转站管理窗口的用户可见文本仍为英文。

本次改造目标：

- 去除三个透明配额窗口四周的 DWM 模糊层，保留清晰的抗锯齿圆角；
- 将额度球轨道和进度弧统一到同一套中心点、半径和线宽；
- 将中转站管理窗口的用户可见文本和辅助功能名称翻译为中文；
- 保留现有额度数据、主题、窗口模式、中转站配置模型和内部枚举值。

非目标：

- 不重新设计完整悬浮窗的布局；
- 不改变中转站请求、凭据、测试或保存逻辑；
- 不改变 `Generic`、`Custom`、`GET`、`POST`、`PUT` 等内部 `Tag` 值。

## 2. 根因

### 2.1 窗口周边发糊

`WpfView.ps1`、`CompactBarView.ps1` 和 `QuotaOrbView.ps1` 都在 `SourceInitialized` 事件中调用 `Enable-MonitorWindowBlur`。该函数通过 `SetWindowCompositionAttribute` 设置 `AccentState = 3`，对整个透明窗口启用背景模糊。透明窗口内容没有覆盖的区域也参与合成，因此圆角和圆形轮廓外出现可见的模糊扩散。

### 2.2 额度球仍显示旧原型

额度球由一个固定 `Ellipse` 轨道和运行时生成的 `Path` 进度弧组成。轨道使用 WPF 元素尺寸，进度弧使用独立的默认半径和坐标。历史提交曾尝试统一两者，但后续提交回滚了相关变更，当前源码仍保留旧组合。运行中的程序还使用安装目录中的副本，源码变化只有重新安装或修复后才会生效。

### 2.3 中转站管理器仍是英文

`RelayManager.xaml` 中窗口标题、字段标签、按钮、展开区标题和辅助功能名称均为英文；`RelayManagerView.ps1` 中信任确认框和部分默认展示文本也为英文。

## 3. 设计

### 3.1 清晰窗口边缘

不再为完整悬浮窗、迷你条和额度球注册或调用 DWM 模糊处理器。窗口继续使用透明背景、布局取整和设备像素对齐；内容背景、圆角和边框由 WPF 自身绘制。

`Enable-MonitorWindowBlur` 保留为独立兼容函数，避免无关公共行为变化，但本次三个视图不再依赖它。

### 3.2 同心额度球

额度球继续保持 112 × 112 的固定窗口和现有交互区域。轨道和进度弧使用共享常量：

- 中心点：`(35, 35)`；
- 半径：与轨道中心线一致；
- 线宽：轨道和进度弧一致；
- 起点：12 点方向；
- 线帽：圆形；
- 100%：使用接近 360 度的完整弧，避免 WPF 同起止点退化。

视觉层级保持为：圆形背景、轨道、进度弧、中央文本、操作按钮。移除 DWM 模糊后，圆球轮廓只由根圆形背景和细边框决定，不再出现额外的模糊圆环。

### 3.3 中转站管理器中文化

翻译以下用户可见内容：

- 窗口标题与辅助功能名称；
- Provider 列表标题以及新增、编辑、复制、删除按钮；
- 启用状态、名称、类型、Base URL、高级请求字段；
- 提取函数、凭据、超时、查询间隔；
- 测试、预览、保存、取消；
- 信任目标确认框和默认结果标签；
- 已禁用 provider 的显示后缀。

技术名词使用一致中文：`中转站`、`通用配置`、`自定义脚本`、`基础地址`、`请求路径`、`查询参数 JSON`、`请求头 JSON`。HTTP 方法和 JSON 保持原文。

## 4. 测试策略

按测试驱动方式实施：

1. 先新增失败测试，要求三个视图不再保存或挂接模糊处理器；
2. 新增失败测试，验证轨道尺寸、中心、半径和进度弧几何一致；
3. 新增失败测试，扫描中转站管理器的用户可见英文，并验证中文标题、按钮和提示框；
4. 修改最少量生产代码使测试通过；
5. 运行相关集成测试及完整 PowerShell 测试套件；
6. 重新安装本地监视器，运行健康与状态检查，并捕获视觉矩阵确认边缘和圆球外观。

## 5. 验收标准

1. 完整悬浮窗、迷你条和额度球外围没有 DWM 模糊扩散；
2. 额度球轨道与进度弧完全同心，线宽和半径一致；
3. 0%、部分进度、100% 和无百分比额度均正常显示；
4. 中转站管理窗口不存在面向用户的英文标题、字段或按钮；
5. 内部枚举值、HTTP 方法、JSON 输入和 provider 数据兼容不变；
6. 重新安装后运行实例加载新界面，普通健康检查为有效状态。

## 6. 风险控制

| 风险 | 控制措施 |
| --- | --- |
| 关闭模糊后半透明背景与桌面混色明显 | 保留现有高不透明度主题背景与细边框 |
| 100% 圆弧退化为空路径 | 继续使用小于 360 度的稳定角度 |
| 中文化误改内部逻辑值 | 仅修改 `Content`、`Text`、`Header`、标题和消息文本，保留 `Tag` 与控件名 |
| 修改源码但运行实例仍使用旧副本 | 完成后执行安装脚本并验证安装目录与运行状态 |
