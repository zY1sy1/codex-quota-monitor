# 中转站独立查询间隔设计

## 目标

移除设置窗口中的全局中转站自动查询间隔，让“管理中转站”中的查询间隔重新成为每个中转站的实际调度依据。所有新建和首次导入的中转站默认每 5 分钟查询一次；已有中转站继续使用各自已保存的间隔。

## 用户界面

- 设置窗口不再显示或编辑“自动查询间隔”。
- 中转站管理器继续显示“查询间隔（分钟，0 为手动）”。
- 中转站管理器继续使用现有的 `0..1440` 整数校验。
- 保存中转站后，新的间隔从重建后的下一轮调度开始生效。

## 调度行为

- 调度器为每个 provider entry 读取该 provider 的 `IntervalMinutes`，不再接受或应用全局覆盖值。
- 大于 `0` 的间隔按每个中转站各自的分钟数自动调度。
- 等于 `0` 的间隔不产生自动查询，但“立即刷新”和管理器中的手动测试仍可发起查询。
- 修改一个中转站的间隔不会改写其他中转站的配置。
- 认证暂停、脚本错误暂停、网络退避、限流重试、并发上限和 sidecar 生命周期保持不变。

## 默认值与导入

- 新增空白中转站的 `IntervalMinutes` 默认值为 `5`。
- 所有内置中转站预设的默认间隔改为 `5`。
- 首次从 CC Switch 导入时，草稿的 `IntervalMinutes` 固定为 `5`，不采用来源描述中的自动查询间隔。
- 更新已经关联的导入中转站时，保留该中转站当前保存的 `IntervalMinutes`。
- 已存在的 `relay-providers.json` 不做批量迁移或改写，因此用户当前保存的 `0..1440` 值保持不变。

## 设置兼容性

- 保持设置 schema 3，避免已安装版本的 `settings.json` 因降级 schema 或字段缺失而被判为损坏。
- `Relay.AutoQueryIntervalMinutes` 暂时作为兼容字段继续被规范化读取和写入，但不在界面显示，也不参与运行时调度。
- 运行时设置快照、设置控制器和设置视图不再传递或修改该兼容字段。
- 后续若要彻底删除兼容字段，应通过单独的设置 schema 升级完成。

## 文档

- README 将查询间隔说明改为每个中转站独立配置，并说明 `0` 的手动模式。
- README 和示例中的新建默认值统一为 5 分钟。
- 不再将设置窗口描述为中转站查询间隔的配置入口。

## 测试

- 调度器单元测试覆盖不同 provider 使用不同间隔，以及单个 provider 为 `0` 时仅能手动刷新。
- 运行时集成测试验证初始加载和 provider 保存后均按各自的 `IntervalMinutes` 重建调度器。
- 设置视图和设置控制器测试验证全局间隔控件及回调已移除。
- 新建草稿、内置预设和首次 CC Switch 导入测试验证默认值为 `5`；导入更新测试验证已有值不变。
- 设置测试继续验证现有 schema 3 全局字段可以安全读取和持久化，但不验证其运行时效果。
- 完整单元、集成和文档合同测试必须通过。
